# 前端展示与性能代码排查（2026-10-28）

本文根据仓库代码整理展示问题与改进建议，不包含内部部署地址、部署目录或实际运行数据。完整内部排查记录仅保留在本地忽略目录，不提交到公开仓库。

## 排查结论

前端需要分别处理首屏资源加载、后台刷新反馈和数据语义。列表接口返回完整任务结果，会进一步增加页面查询、下载和解析开销。应先修正这些直接问题，再根据性能测量决定是否需要更复杂的架构。

## 首屏加载

- 为正式访问发布构建产物，避免将开发服务器作为长期使用入口。
- 图表和配置抽屉按需加载，避免无关模块进入首屏依赖链。
- `frontend/src/styles/global.css` 通过 CSS import 引用外部字体；优先使用系统字体或本地字体，减少外部网络依赖。
- `OverviewView.vue` 使用一个 Promise.allSettled 等待三个列表，再统一结束 loading。应让各区域独立展示已返回的数据，并明确表达部分失败。
- `stores/models.ts` 只判断是否已有数据，没有复用进行中的请求；多个组件同时挂载时可能重复请求模型列表。

## 压测列表刷新

`StressView.vue` 的 reload 每次都会开启 loading，而任务表绑定了 v-loading。首次加载与后台轮询共用这一状态，导致正常更新也会遮住表格。

应区分首次加载、手动刷新和后台更新。后台保留内容、焦点、滚动位置和选中项，复用进行中的请求；切换任务时校验任务 ID 或使旧请求失效，防止慢响应覆盖当前详情。产物列表应在选择任务或确认任务完成时更新，避免每轮清空重拉。

能力评测页也需要检查相同的轮询、loading 与详情选择行为。

## 并发、速率和指标单位

当前详情表使用：

```ts
row.rate ?? row.parallel ?? '—'
```

EvalScope 的 rate=-1 表示不限请求速率，开环模式的 parallel=-1 表示不限并发。空值合并不会跳过 -1，因此这个表达式可能遮住真实并发值。

应依据 request_config.open_loop 和有效档位值展示：闭环显示并发，开环显示速率及 req/s；不限速或不限并发用文字表达，缺失值显示“—”。历史任务缺少模式字段时，应按有效的正数速率或并发兜底。保留 raw_result 的原始语义。

图表横轴也要区分并发和速率。请求吞吐与 Token 吞吐应明确区分 req/s 和 tok/s，避免使用统一但错误的单位。

## 展示真实性与操作完整性

| 问题 | 代码依据与改进方向 |
| --- | --- |
| 示例任务默认展示 | RunningTasks 的 tasks 默认值是演示任务，OverviewView 未传真实 tasks；没有数据时应显示空态 |
| 失败任务可能消失 | 压测归组的 included 只保留有 runs 或 running/pending 的记录；应保留失败和中断任务 |
| 分组可能掩盖失败 | completed 的优先级高于 failed；混合结果需要表达部分失败 |
| 默认分组缺少控制入口 | 取消、进度和产物入口主要限定非 grouped；应提供组内成员钻取 |
| 部分按钮仅弹提示 | 批量重新运行、部分配置和重试按钮未接入真实动作；实现前应禁用并解释 |
| KPI 名称与含义不符 | “在线模型”实际统计配置数，“通过率”实际统计任务完成比例；改为准确的描述并注明统计窗口 |
| 统计可能不完整 | 概览对列表截断后的数据计算今日数量和比例；应使用完整聚合统计 |
| 压测对比不完整 | 入口只传一个 types=stress，对比页后续列默认 basic；指标表只读取基础评测 results，尚未接入压测摘要 |

## P0 改进建议

| 顺序 | 改进要求 | 验收条件 |
| --- | --- | --- |
| 1 | 删除示例数据并纠正统计语义 | 所有数值可追溯到真实 API；空数据与请求失败分别表达 |
| 2 | 修正并发、速率、特殊值与单位 | 闭环展示真实并发；开环展示速率；未知值不会被伪装为零 |
| 3 | 保留失败任务并补齐控制入口 | 失败和中断记录可找到；分组不能掩盖成员失败；可进入详情并取消真实任务 |
| 4 | 后台更新不遮挡用户操作 | 无整表反复 loading；请求不重叠；切换任务不串数据 |
| 5 | 正式构建交付并减少首屏依赖 | 入口不包含开发客户端；录制冷缓存 Network 和 LCP 验证效果 |
| 6 | 列表摘要化与共享查询 | 列表不携带 raw_result；原始结果按需获取；计数不依赖截断列表 |

列表减负需要后端配合。现有三个任务 store 都先读取并解析全部 JSON、排序后再截断，limit 不能限制磁盘扫描量。先缩小响应和减少重复请求，再按测量结果决定是否需要索引。

正式交付可参考 [Vite 官方静态部署说明](https://vite.dev/guide/static-deploy.html)。本项目构建输出目录为 app/web_vue；FastAPI 保持 API-only。vite preview 用于本地预览。
